내 NAS의 Google Calendar 연결

본인의 Google Cloud 프로젝트로 사건 전용 캘린더를 연결합니다.

사건 관리로 돌아가기 ↗

설치자마다 자신의 Google Cloud 프로젝트와 웹 OAuth 클라이언트를 준비합니다. NAS 관리자 화면에 JSON을 한 번 등록한 뒤 본인 Google 계정으로 승인하면, NAS가 사건 기일을 사건 관리 전용 캘린더에 반영합니다. 캘린더 연동은 선택 사항입니다. 개인정보처리방침

1. NAS 첫 실행 2. 콜백 주소 준비 3. Google 프로젝트와 API 4. 동의 화면과 권한 5. 웹 OAuth JSON 만들기 6. NAS에서 계정 연결 7. 일정 반영 확인 오류별 해결 인증정보와 연결 해제 설정을 맡기는 경우 공식 자료

1. NAS에서 사건 관리 열기

  1. 시놀로지용 compose.synology.yaml을 Container Manager의 프로젝트로 실행합니다. 배포 이미지는 Intel/AMD x86_64 기준이며, 기본 접속 포트는 7708입니다. 시놀로지 설치 안내 · Container Manager 프로젝트 도움말
  2. 같은 네트워크의 PC에서 http://NAS의-IP:7708로 접속해 처음 설정 화면에서 8~256자의 관리자 비밀번호를 두 번 입력합니다. 이미 사용하던 NAS는 기존 관리자 비밀번호로 로그인합니다.
  3. 설정 → Google Calendar 연결 → 처음부터 따라 하는 상세 안내를 엽니다. 현재 HTTP IP 주소는 초기 접속 확인에 사용하고, 실제 Google 연결은 2단계에서 준비한 주소로 로그인해 진행합니다.

2. Google 로그인 뒤 돌아올 주소 준비

콜백 URI는 Google 로그인과 권한 승인 뒤 브라우저가 돌아오는 주소입니다. 실제로 사건 관리에 접속할 주소에 /oauth/google/callback을 붙입니다. Google의 웹 OAuth는 HTTPS 주소 또는 localhost 예외를 허용하며, 스킴·호스트·포트·경로가 등록값과 정확히 일치해야 합니다. Google 리디렉션 URI 규칙

방법 A. 유효한 인증서가 있는 HTTPS 주소 사용

  1. 이미 사건 관리가 HTTPS로 열리면 그 주소를 사용합니다. 새로 만들 경우 소유하거나 사용하도록 허가받은 도메인이나 Synology DDNS 호스트 이름을 준비합니다. Synology DDNS 설정
  2. DSM의 제어판 → 보안 → 인증서에서 호스트 이름에 맞는 TLS 인증서를 등록합니다. Synology의 Let's Encrypt 인증서 발급 방법
  3. 제어판 → 로그인 포털 → 고급 → 역방향 프록시 → 생성에서 아래 예시를 적용합니다. court.example.com은 자신의 호스트 이름으로 바꿉니다. 대상은 기본 시놀로지 Compose가 열어 둔 NAS 내부 포트입니다. DSM 역방향 프록시 도움말
항목소스대상
프로토콜HTTPSHTTP
호스트 이름court.example.com127.0.0.1
포트4437708

역방향 프록시를 만든 뒤 제어판 → 보안 → 인증서 → 설정에서 해당 서비스에 등록한 인증서를 지정합니다. 브라우저에서 https://court.example.com을 열어 사건 관리 로그인 화면과 유효한 인증서를 확인합니다. 그 주소로 로그인한 뒤 이 안내를 다시 열면 예시 콜백은 https://court.example.com/oauth/google/callback입니다. Google 승인에 사용하는 브라우저에서 그 주소에 접속할 수 있어야 합니다.

방법 B. HTTPS 주소 없이 PC의 localhost SSH 터널 사용

  1. NAS에 SSH로 접속할 수 있는 PC에서 터미널 또는 PowerShell을 엽니다. NAS사용자와 NAS-IP를 자신이 사용하는 접속 정보로 바꿔 아래 명령을 실행합니다. DSM SSH 서비스의 기본 포트는 22이며, 별도 포트를 쓰면 SSH 명령에 -p 포트번호를 추가합니다. DSM SSH 서비스 설정
ssh -N -L 7708:127.0.0.1:7708 NAS사용자@NAS-IP
  1. 터미널을 열어 둔 채 같은 PC의 브라우저에서 http://localhost:7708로 로그인합니다. 이 경우 등록할 주소는 http://localhost:7708/oauth/google/callback입니다.
  2. PC의 7708 포트가 이미 사용 중이면 명령의 앞쪽 포트만 17708 등으로 바꿉니다. 브라우저 주소와 콜백 URI에도 그 포트를 사용합니다. Google 권한 승인과 전용 캘린더 생성이 끝나면 터널을 닫아도 NAS가 인터넷에 연결되어 있는 동안 일정 반영이 계속됩니다.

Google Cloud에 등록할 주소로 이 안내를 열면 위 칸에서 콜백 URI를 확인할 수 있습니다.

3. Google Cloud 프로젝트를 준비하고 Calendar API 켜기

캘린더를 사용할 Google 계정으로 콘솔에 로그인합니다. 프로젝트를 만든 계정과 Google 연결에 사용할 계정을 함께 확인해 두면 승인 단계에서 계정이 섞이는 일을 줄일 수 있습니다. Google Cloud 콘솔 열기

본인 Google 계정 하나를 연결하는 새 설치

  1. 개인 모드(Personal mode) 설정 페이지에서 새 프로젝트를 만들거나 이미 준비한 개인 모드 프로젝트를 선택합니다. 처음 만든 Google 계정 한 개가 해당 앱을 승인할 수 있습니다. Google은 이 모드를 OAuth 앱 검증, 신규 사용자 한도, 테스트 토큰 7일 만료의 적용 대상에서 제외합니다. 이후 다른 Google 계정도 승인해야 한다면 별도의 외부용 프로젝트를 사용합니다. 개인 모드 설정 시작 · Google 개인 모드 도움말
  2. 이 화면에서 웹 OAuth 클라이언트도 한 번에 만들 수 있습니다. 유형과 콜백 URI는 5단계의 입력값을 사용하고, 생성 팝업이 뜨면 JSON 다운로드를 누릅니다.
  3. 콘솔 상단에서 방금 설정한 프로젝트를 선택해 Google Calendar API → 사용을 누릅니다. 개인 모드에서 클라이언트를 먼저 만들었어도 API가 켜진 뒤 NAS 연결을 진행하면 됩니다. Google Calendar API 사용 설정

기존 프로젝트를 사용하거나 여러 Google 계정에 승인받는 설치

  1. 콘솔 상단 프로젝트 선택기에서 사용할 프로젝트를 선택하거나 새 프로젝트를 만듭니다. 실제로 작업하는 프로젝트의 이름과 ID를 기록합니다. 새 프로젝트 만들기 · Google Cloud 프로젝트 안내
  2. 그 프로젝트에서 API 및 서비스 → 라이브러리 → Google Calendar API → 사용을 누릅니다. 화면에 관리가 나오면 API가 이미 켜져 있습니다. 다음 단계의 동의 화면과 클라이언트도 같은 프로젝트에 둡니다. Google Calendar API 열기

4. 동의 화면과 캘린더 권한 설정

3단계에서 개인 모드 클라이언트를 만든 경우 5단계에서 JSON과 콜백을 확인합니다. 외부 또는 조직 내부용 프로젝트라면 Google Auth Platform에서 아래 항목을 준비합니다. Google Auth Platform 열기 · 동의 화면과 권한 설정 도움말

  1. 브랜딩(Branding)에서 공개 앱 홈페이지의 이름과 일치하도록 앱 이름을 사건정보연동으로 정하고, 사용자 지원 이메일과 개발자 연락처를 지정합니다. 외부 공개용으로 게시할 때 필요한 홈페이지, 개인정보처리방침, 이용약관, 도메인 소유권은 Google의 안내를 따릅니다. 로고를 올리는 경우 권장 크기는 120×120픽셀이며 파일은 최대 1MB입니다. 브랜딩 설정 열기 · 브랜딩과 승인된 도메인 도움말
  2. 대상(Audience)에서 개인 Gmail을 포함하는 앱은 외부(External)를, Workspace 조직 구성원으로 제한할 앱은 내부(Internal)를 선택합니다. 외부 앱이 테스트 중(Testing)이면 테스트 사용자 추가를 눌러 실제로 연결할 Google 이메일을 저장합니다. 대상 설정 열기 · 사용자 유형과 게시 상태 도움말
  3. 데이터 액세스(Data Access) → 범위 추가 또는 삭제에서 아래 범위를 선택하고 저장합니다. 목록에 보이지 않으면 Calendar API가 같은 프로젝트에서 켜져 있는지 확인하고, 콘솔에 직접 입력 기능이 있으면 아래 주소를 붙여 넣습니다. 앱이 만든 보조 캘린더와 그 일정에 대한 권한입니다. 데이터 액세스 열기 · Google Calendar 권한 목록
https://www.googleapis.com/auth/calendar.app.created

외부 앱의 테스트 모드 승인은 7일 동안 유효합니다. Calendar 권한을 승인한 뒤 7일이 지나면 Google 갱신 토큰도 만료됩니다. 장기 운영 시 대상 → 앱 게시(Publish app)에서 프로덕션(In production)으로 전환하고 콘솔의 권한 분류에 따라 필요한 검증을 완료합니다. 게시 후 NAS에서 다시 승인합니다. 테스트 만료와 사용자 한도 · OAuth 앱 검증 도움말

콘솔에 표시된 100명 한도. 테스트 모드에서는 프로젝트의 테스트 사용자 목록에 최대 100명을 등록할 수 있습니다. 별도로 미승인 민감·제한 권한에 대한 신규 승인 사용자 100명 한도가 있습니다. 한도는 Google Cloud 프로젝트를 기준으로 적용됩니다. 이 안내에 따라 설치자별로 본인 프로젝트에서 승인합니다. Google OAuth 사용자 한도 설명

5. 웹 애플리케이션 OAuth 클라이언트와 JSON 준비

  1. 같은 프로젝트의 Google Auth Platform → 클라이언트(Clients) → 클라이언트 만들기를 엽니다. 개인 모드 설정 화면에서 바로 만드는 경우에도 아래와 같은 값을 사용합니다. 구형 메뉴는 API 및 서비스 → 사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID에서 찾을 수 있습니다. 클라이언트 설정 열기
  2. 애플리케이션 유형에서 웹 애플리케이션을 고르고 이름을 내 NAS 사건 일정 등으로 입력합니다. 승인된 JavaScript 원본 칸은 비워 둡니다. 이 앱은 서버에서 인증 코드를 교환합니다.
  3. 승인된 리디렉션 URI(Authorized redirect URIs) → URI 추가에 2단계에서 복사한 콜백 주소를 그대로 붙여 넣습니다. 포트가 있는 주소는 포트까지 포함하고 /oauth/google/callback 뒤에 슬래시를 덧붙이지 않습니다.
  4. 만들기를 누른 뒤 생성 창에서 JSON 다운로드를 눌러 파일을 안전한 곳에 저장합니다. Google의 현재 정책상 전체 클라이언트 시크릿은 생성할 때 다운로드할 수 있습니다. 창을 닫기 전에 다운로드를 확인합니다. 클라이언트 생성과 시크릿 보관 방법
  5. 이 파일에는 최상위 web 항목과 그 아래 client_id, client_secret, redirect_uris가 있습니다. 실제 시크릿이 든 파일은 본인 NAS에 업로드하고 별도 보관본은 비공개 위치에 둡니다.

콜백 주소가 바뀌었거나 파일을 잃어버렸을 때

  • 주소가 달라졌다면 먼저 Google 콘솔에서 승인된 URI를 변경하고 저장합니다. 보관한 JSON의 사본에서 web.redirect_uris 목록도 새 콜백에 맞춰 갱신한 뒤 NAS에 올립니다. 주소가 Google 콘솔과 JSON 양쪽에 있어야 합니다.
  • 다운로드한 파일과 시크릿을 잃어버렸다면 같은 클라이언트의 시크릿 추가 기능으로 새 시크릿을 만들고 새 값을 생성할 때 저장합니다. 콘솔에서 JSON이 제공되면 다운로드하고, 시크릿만 받았다면 아래 형식을 참고해 로컬 파일로 저장합니다. 실제 값은 본인 콘솔과 2단계의 콜백 주소를 사용합니다. Google 클라이언트 시크릿 교체 안내
{
  "web": {
    "client_id": "콘솔에 표시된 전체 클라이언트 ID",
    "client_secret": "새 시크릿의 전체 값",
    "redirect_uris": ["https://court.example.com/oauth/google/callback"]
  }
}

클라이언트 설정이 달라진 JSON을 올리면 앱이 이 NAS의 기존 연결 정보를 초기화합니다. 계정 승인을 다시 마친 뒤 Calendar에서 사용할 사건 전용 캘린더를 확인합니다. 연결 과정에서 전용 캘린더가 새로 만들어질 수 있습니다.

6. NAS에 JSON을 등록하고 내 Google 계정 승인

  1. Google 콘솔에 등록한 콜백과 같은 호스트·프로토콜·포트로 사건 관리에 로그인합니다. 설정 → Google Calendar 연결 → 최초 1회: 내 Google OAuth 앱 등록을 펼칩니다.
  2. OAuth JSON 선택하여 등록을 누르고 준비한 웹 클라이언트 JSON을 선택합니다. 등록 메시지가 뜨면 Google 계정 연결을 누릅니다.
  3. Google에서 실제로 캘린더를 소유할 계정을 골라 권한을 승인합니다. 개인 모드는 프로젝트를 만든 계정, 외부 테스트 모드는 등록해 둔 테스트 계정을 선택합니다. 연결 요청은 10분 이내에 같은 브라우저와 NAS 주소에서 끝냅니다.
  4. 사건 관리로 돌아와 연결됨 · 사건 관리 전용 캘린더가 표시되는지 확인합니다. Google 승인은 끝났는데 캘린더 생성에 실패한 경우, 같은 프로젝트의 Calendar API 상태를 확인하고 전용 캘린더 준비 다시 시도를 누릅니다.
  5. 승인한 계정으로 Google Calendar를 열고 왼쪽 내 캘린더에서 사건 관리를 찾습니다. 목록에 있으면 체크 표시를 켜 일정이 보이게 합니다. Google Calendar 열기

7. 기일 반영과 다시 연결 확인

  1. 조회 권한이 있는 사건을 등록하고 지금 확인을 누르거나 자동 조회를 기다립니다. 사건 상세에서 차회 기일이 확인되는지 봅니다.
  2. 캘린더 반영 대기가 해소되고 사건 관리 캘린더에 같은 날짜와 시간의 일정이 표시되는지 확인합니다. 아직 기일이 없는 사건은 법원에서 기일이 확인되는 시점에 일정이 생깁니다.
  3. Google 승인 만료가 표시되면 설정 → Google Calendar 연결 → Google 계정 다시 연결에서 같은 계정을 승인합니다. 토큰이 만료된 이유는 Google의 만료 조건과 콘솔의 게시 상태에서 확인할 수 있습니다. Google 갱신 토큰 만료 조건

컨테이너를 업데이트하거나 재시작할 때 기존 court_data 볼륨을 사용합니다. 이 볼륨에 보관한 사건, 자동 조회 예약, Google 연결을 이어서 사용합니다.

내 NAS의 Google Calendar 연결

Compose 수정 없이 시작하고, 내 Google 계정은 내 NAS에서 직접 인증합니다.

사건 관리로 돌아가기 ↗

처음 한 번 OAuth 앱을 등록하면 이후에는 Google 계정 연결 → 계정 선택 → 권한 승인으로 연결합니다. 공통 인증 서버는 사용하지 않습니다. 여러 사용자가 설치하면 각자의 NAS·Google 계정·OAuth 앱·DB가 서로 분리됩니다.

설정을 맡기려면 이것만 준비하세요

  1. NAS에서 이 프로그램이 열리고 관리자 로그인이 되는지 확인합니다.
  2. 아래 ‘돌아올 주소’ 단계에 따라 실제로 접속할 HTTPS 주소 또는 localhost 터널 주소를 준비합니다.
  3. Google Cloud Console을 열고 캘린더를 소유할 본인 Google 계정으로 로그인합니다. 기존 프로젝트를 쓸지 새 프로젝트를 만들지만 정하면 됩니다.
  4. 아래 요청문을 복사해 설정을 도와주는 사람이나 코딩 도우미에게 전달합니다. 로그인·본인 확인은 본인이 완료하고, 앱 생성·권한 승인 단계에서는 내용을 확인합니다.

이 페이지에 표시된 콜백 주소는 지금 이 페이지를 연 주소를 기준으로 만듭니다. 아직 HTTP IP 주소로 보고 있다면 먼저 2단계를 마친 다음 올바른 주소로 이 안내를 다시 여세요.

Google 비밀번호·일회용 인증번호·클라이언트 시크릿은 요청문이나 채팅에 넣을 필요가 없습니다. 내려받은 OAuth JSON은 NAS 화면에 직접 등록하면 됩니다.

1. 시놀로지에서 처음 실행하기

  1. Container Manager의 프로젝트에서 제공된 compose.synology.yaml을 그대로 실행합니다. 설치 경로에 소스코드나 Google 키 파일을 둘 필요가 없습니다.
  2. http://NAS의-IP:7708로 접속합니다. Intel/AMD x86_64용 이미지이며 NAS 방화벽을 쓰면 사용하는 네트워크에서 7708 포트에 접근할 수 있어야 합니다.
  3. 처음 설정 화면에서 관리자 비밀번호를 두 번 입력합니다. 길이는 16~256자입니다. 설정 후 자동으로 로그인합니다.
  4. 이미 초기 설정된 DB라면 로그인 화면이 나옵니다. 기존 비밀번호를 사용하세요. 비밀번호는 웹 화면에서 바꾸며 Compose를 수정하지 않습니다.

프로젝트의 court_data 볼륨은 비밀번호·세션·사건·조회 예약을 보관합니다. 이미지 업데이트 때 볼륨을 삭제하지 마세요.

2. Google 로그인 후 돌아올 주소 준비

Google은 승인된 리디렉션 URI를 정확히 비교합니다. NAS마다 주소가 달라도 각자의 OAuth 앱에 자신의 주소를 등록하면 됩니다. http://192.168.…:7708 같은 일반 HTTP IP 주소는 사용할 수 없습니다.

방법 A — HTTPS 주소로 접속

  1. 본인의 도메인이나 Synology DDNS 주소와 유효한 HTTPS 인증서를 준비합니다. DSM의 DDNS·인증서 안내는 아래 공식 자료에 있습니다.
  2. DSM 제어판 → 로그인 포털 → 고급 → 역방향 프록시에서 해당 주소를 사건 관리 프로그램으로 연결합니다. 예: 원본 HTTPS / court.example.com / 443, 대상 HTTP / 127.0.0.1 / 7708. 호스트 이름은 본인 주소로 바꿉니다.
  3. 해당 호스트에 맞는 인증서를 연결합니다. 기존 443 서비스가 있으면 호스트 이름이 충돌하지 않도록 설정합니다. 공유기·방화벽·DNS 설정은 사용 중인 네트워크 환경에 맞아야 합니다.
  4. https://본인주소로 열었을 때 DSM이 아니라 사건 관리 로그인 화면이 나오는지 확인합니다. 브라우저의 인증서 오류가 없는 주소를 사용합니다.
  5. 그 HTTPS 주소에서 로그인하고 이 안내를 다시 열어 아래 콜백 주소를 복사합니다.

방법 B — HTTPS 도메인이 없으면 localhost SSH 터널

본인의 PC에서 NAS로 SSH 터널을 열면 Google이 허용하는 localhost 주소로 최초 인증할 수 있습니다. NAS에 SSH 접속할 권한과 PC의 SSH 클라이언트가 있는 경우 사용합니다.

ssh -N -L 7708:127.0.0.1:7708 NAS사용자@NAS-IP

터널을 연 PC의 브라우저에서 http://localhost:7708로 접속해 로그인합니다. Google Cloud에 등록할 URI는 http://localhost:7708/oauth/google/callback입니다. PC의 7708 포트가 사용 중이면 터널의 앞쪽 포트를 바꾸고 변경된 localhost 포트로 등록합니다. 인증을 마치고 터널을 닫아도 NAS가 Google에 접속할 수 있으면 예약 조회·캘린더 갱신은 계속됩니다.

Google 인증 후 브라우저가 이 주소로 돌아옵니다. 다른 PC나 주소로 인증을 시작했다가 바꾸면 해당 브라우저의 로그인 세션이 없어 실패할 수 있습니다.

3. 본인 Google 프로젝트와 Calendar API

  1. Google Cloud Console에서 상단 프로젝트 선택기를 엽니다.
  2. 기존 프로젝트를 선택하거나 새 프로젝트를 만듭니다. 프로젝트 이름은 예를 들어 나의 사건 일정처럼 정합니다. 계정에 프로젝트 생성 권한이 없다면 소유자에게 권한을 요청합니다.
  3. API 및 서비스 → 라이브러리에서 Google Calendar API를 검색하고 사용을 누릅니다.
  4. 프로젝트를 바꿔 가며 설정하지 않도록 프로젝트 이름·ID를 확인합니다. 다음 단계의 OAuth 클라이언트도 같은 프로젝트에서 만듭니다.

4. OAuth 동의 화면과 사용자 등록

콘솔 화면에 따라 Google Auth Platform 또는 API 및 서비스 → OAuth 동의 화면으로 표시됩니다. 메뉴 이름은 Google의 업데이트에 따라 조금 달라질 수 있습니다.

  1. 브랜딩 / Branding에서 앱 이름, 사용자 지원 이메일, 개발자 연락처를 입력합니다. 개인용 앱 이름은 나의 사건 일정 등으로 정합니다.
  2. 대상 / Audience에서 개인 Google 계정은 보통 External을 사용합니다. 조직 전용 Internal은 해당 Workspace 조직에 속할 때만 선택합니다.
  3. Testing 상태이면 테스트 사용자에 실제 연결할 본인 Google 이메일을 추가합니다. 조직 정책으로 앱 사용이 막힌 계정은 조직 관리자 확인이 필요합니다.
  4. 데이터 액세스 / Data Access에서 이 프로그램이 요청할 아래 권한을 확인합니다. 기존 개인 일정 전체를 수정하는 광범위한 권한을 추가할 필요는 없습니다.
https://www.googleapis.com/auth/calendar.app.created

이 권한은 이 OAuth 앱이 만드는 보조 캘린더와 그 일정을 관리하는 범위입니다. 사용자별로 본인의 OAuth 앱을 사용하므로 다른 NAS 운영자의 연결 정보가 필요하지 않습니다.

계속 운영하려면 Testing 상태를 확인하세요. External 앱이 Testing인 상태에서는 Calendar 권한의 갱신 토큰이 보통 7일 후 만료됩니다. 장기 자동 운영 전에 Audience의 게시 상태와 Google이 요구하는 앱 확인·게시 절차를 완료하세요. ‘로그인 90일 유지’는 NAS 관리자 로그인 설정이며 이 Google 정책을 연장하지 않습니다.

5. 웹 애플리케이션 OAuth 클라이언트 만들기

  1. Google Auth Platform → 클라이언트 / Clients 또는 API 및 서비스 → 사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID를 엽니다.
  2. 애플리케이션 유형은 반드시 웹 애플리케이션을 선택합니다. 서비스 계정, 데스크톱 앱, TV용 클라이언트가 아닙니다.
  3. 알아보기 쉬운 이름을 입력합니다. 이 서버 방식에는 승인된 JavaScript 원본을 별도로 입력할 필요가 없습니다.
  4. 승인된 리디렉션 URI / Authorized redirect URIs에 2단계의 콜백 URI를 붙여 넣습니다. 프로토콜, 도메인, 포트, /oauth/google/callback 경로를 모두 포함합니다. 마지막에 슬래시를 덧붙이지 않습니다.
  5. 만들기로 생성하고 OAuth 클라이언트의 JSON 다운로드를 받습니다. JSON의 최상위에 web 항목이 있어야 합니다.
  6. URI를 나중에 추가·변경했다면 저장한 뒤 JSON도 다시 내려받아 NAS에 다시 등록합니다. 이전에 받은 파일에는 변경 내용이 들어 있지 않습니다.

개인 키를 만드는 서비스 계정 절차가 아닙니다. 사용자 본인의 로그인 동의를 받아 본인 소유 캘린더를 만들기 위한 OAuth 클라이언트입니다.

6. NAS 화면에서 Google 계정 연결

  1. URI에 등록한 주소로 사건 관리 화면에 접속하고 로그인합니다.
  2. Google Calendar 연결 → 최초 1회: 내 Google OAuth 앱 등록을 펼칩니다.
  3. OAuth JSON 선택하여 등록을 눌러 내려받은 웹 클라이언트 JSON을 선택합니다. Compose나 이미지에 JSON 내용을 넣지 않습니다.
  4. Google 계정 연결을 누릅니다. Google 로그인 화면에서 사용할 계정을 선택하고, 사건 전용 캘린더 생성·일정 관리 권한을 확인한 뒤 승인합니다.
  5. 같은 NAS 주소로 돌아오면 프로그램이 본인 Google 계정에 사건 관리 보조 캘린더를 생성합니다. 생성 중 오류가 나면 전용 캘린더 준비 다시 시도를 사용할 수 있습니다.
  6. 관리 화면에 연결됨 · 사건 관리 전용 캘린더가 나오는지 확인합니다. Google Calendar의 내 캘린더 목록에서 캘린더가 숨겨져 있지 않은지도 확인합니다.

OAuth 클라이언트 JSON, Google 장기 연결 토큰은 이 NAS의 DB에 암호화해 저장합니다. 운영자의 공통 인증 서버로 보내지 않습니다. 이후 관리자로 다시 로그인하는 것만으로 Google 계정을 매번 재승인할 필요는 없습니다.

7. 실제 동작과 재시작 확인

  1. 본인이 조회할 수 있는 사건을 등록하고 조회가 완료되는지 확인합니다.
  2. 차회 기일이 있는 사건이면 캘린더 반영 대기가 해소되고, 사건 관리 캘린더에 일정이 생기는지 확인합니다. 기일이 없는 사건은 일정이 없을 수 있습니다.
  3. 선고 예정 시각이 확인되면 기본 30분 후부터 주문을 확인합니다. 선고 후 추가 확인은 09~19시·30분 간격·하루 최대 8회이며, 미확인 상태는 다음 날에도 이어집니다.
  4. 컨테이너를 재시작해 사건 목록·마지막 조회·다음 확인 시각이 유지되는지 확인합니다. NAS를 껐던 동안에는 조회할 수 없고, 다시 시작하면 DB의 남은 예약을 기준으로 이어갑니다.
  5. 최근 작업 또는 사건 상세에 Google 인증 만료가 표시되면 Google 계정 다시 연결로 승인합니다. 자동 조회를 중지했다면 화면에서 재개합니다.

동일 DB 볼륨을 사용하면 관리자 세션도 기본 90일의 남은 기간 동안 유지됩니다. 쿠키 삭제·시크릿 모드·다른 도메인 접속은 별도 로그인입니다.

재시작 후 비밀번호 설정 화면이 다시 표시됨기존 데이터 볼륨과 다른 프로젝트·새 볼륨을 사용했는지 확인합니다. 빈 DB에 임의로 새 비밀번호를 만들기 전에 기존 볼륨·백업 위치를 확인하세요.
인증정보 복호화 실패SQLite DB와 같은 볼륨의 credentials.key가 한 쌍인지 확인합니다. 둘을 함께 백업·복원해야 합니다.

관리자 비밀번호는 원문 대신 임의 salt를 적용한 PBKDF2 해시로, 관리자 세션 토큰도 해시로 저장합니다. Google 클라이언트 시크릿과 토큰은 NAS의 암호화 키로 암호화합니다. DB와 키는 같은 court_data 볼륨에 있고 별도 DB 컨테이너는 필요하지 않습니다. 이미지·GitHub 저장소에는 실제 키·토큰·사건 이력을 포함하지 않습니다.

이 NAS의 연결 해제는 저장된 토큰을 삭제하고 자동 캘린더 전송을 멈춥니다. Google에 이미 만들어진 캘린더·일정은 삭제하지 않습니다. Google 계정의 타사 앱 연결 화면에서 앱의 권한도 취소할 수 있습니다. NAS의 관리자·파일시스템 접근자는 해당 NAS를 관리하므로, DB 암호화만으로 NAS 관리자에게서 정보를 숨기는 구조는 아닙니다.

백업은 DB 파일만이 아니라 데이터 볼륨 전체를 보관하세요. 최초 설정이 끝난 기존 볼륨에 새 Compose를 적용해도 기존 비밀번호를 덮어쓰지 않습니다.
